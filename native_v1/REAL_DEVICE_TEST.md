# v1 Native Alpha — 两台实体电脑验收

> 本测试只针对 v1 Native Alpha。不要与 v0.9.0 同时运行。

## 目标

先验证最核心的一件事：两台真实 Windows / macOS 电脑能否通过原生 QUIC 通道完成配对，并实现鼠标跨屏 + 键盘跟随。

v1 不再使用 Deskflow，也不使用 TCP 24800。默认网络为：

- UDP 47833：局域网发现
- UDP 47834：QUIC / TLS 1.3 键鼠与剪贴板通道

## Windows -> Windows 首轮测试

1. 两台电脑都彻底退出旧 v0.9.0；Windows 任务管理器中确认没有旧的 `ShifanAI-HostShare.exe` / `deskflow-core.exe`。
2. 两台电脑都安装同一个 v1 Native Alpha Windows 安装包并打开。
3. 物理连接键盘鼠标的电脑选择 **服务端**。
4. 另一台电脑选择 **客户端**，保持软件打开。
5. 服务端进入“设备”页，点击 **扫描局域网**。正常情况下应直接发现客户端，不需要输入 IP。
6. 服务端对发现的客户端点击 **配对**。
7. 客户端会显示 `XXXX-XXXX-XXXX` 配对码。
8. 服务端输入该配对码；输入过程中每 4 个字符自动加入 `-`，完成配对。
9. 服务端把客户端屏幕拖到真实物理位置（左 / 右 / 上 / 下）。
10. 开启键鼠共享，把鼠标推到对应屏幕边缘。

### 通过标准

- 服务端可以扫描到客户端；
- 配对码验证成功；
- 鼠标越过边缘后进入第二台电脑；
- 键盘焦点跟随鼠标；
- 鼠标滚轮有效；
- Ctrl+C / Ctrl+V 文本剪贴板至少成功一次；
- 点击停止后立即停止控制，不出现按钮卡在“连接中”；
- 再次启动能够恢复连接，不需要重新输入 IP。

## 如果失败

不要再根据“可能是防火墙”去猜。直接在 **设置 -> 诊断 -> 复制诊断信息**，把两台电脑各自的诊断文本发回来。

诊断至少应包含：实际发现端口、QUIC 端口、已发现设备、配对状态、权限状态和日志目录。这样可以定位到 discovery / pairing / QUIC / input capture / input injection 的具体一层。

## Windows / macOS

Windows -> Windows 通过后再测试：

1. Windows 服务端 -> macOS 客户端；
2. macOS 服务端 -> Windows 客户端。

macOS 首次运行必须允许辅助功能 / 输入监控权限。没有这些系统权限时，应用可以联网但无法正常捕获或注入键鼠事件。

## 版本门槛

只有 Win -> Win 真机完成鼠标跨屏和键盘跟随后，版本才从 `alpha` 提升到 `beta`。Win <-> macOS 和稳定性测试完成后才标记 stable。
